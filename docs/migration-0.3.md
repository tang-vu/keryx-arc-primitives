# Migrating 0.2 to 0.3

This is a breaking safety release. Review integration authority before using live funds.

- `TollOptions.priceUsdc` is now an exact decimal string. Replace floating reward multiplication with `allocateMicros`; explicit zero/free endpoints belong outside the paid seller. Network/asset/Gateway overrides were removed: this extraction remains Arc testnet.
- Paid `settleThenServe` calls require a durable `SellerJournal`. Implement a transactional unique key by network, asset, payer and nonce across every resource. Claim persists the original identity/payload; `submitted` precedes any debit; `settled` records verified evidence before delivery. Repeated claims return retained conflict, not automatic paid replay. Recovery/delivery replay is host-owned.
- Seller settlement is called once. Throws, negative or malformed settlement responses remain pending. Storage acknowledgement loss is retained; after confirmed settlement the response preserves payment evidence even if durable acknowledgement or delivery fails. Never generate a fresh payment authorization just because HTTP delivery failed.
- `SettleInfo` exposes exact `amountMicros`, nonce and payment identity; the transaction string is Circle settlement evidence, not necessarily an EVM hash.
- Global `setGrant/canSpend/recordSpend` helpers are removed. Instantiate `MemoryGrantStore` and synchronously `reserve` before any signing exposure. All amounts are bigint micro-USDC. Replacement and signer aliases cannot reset the store's budget. Only a prepared, unexposed reservation can cancel; no expiry/revoke/unknown-failure release. Persist a real production ledger instead of retaining this in-memory demonstration.
- `BuyerOptions.chain` was removed. The existing SDK `chain`/`rpcUrl` constructor fields are still valid in 3.5.0; the buyer is now explicitly testnet-only. It holds a server key and is not subject to browser reference-store caps. The host owns challenge validation, spend admission and recovery.
- `WithdrawIntentOpts.maxFeeUsdc` is required and string-valued; `maxBlockHeight` is a required finite source-chain ceiling, also bounded by relay policy. Do not assume a hard-coded withdrawal fee reserve. The relay requires a selected authenticated policy, gas cap and durable journal. Its result uses exact `amountMicros`; ambiguous errors include retained request identity and a locally prepared transaction hash when available.
- Relay journals uniquely claim both BurnIntent digest and TransferSpec hash/salt, preventing a re-signed fee/height variant from sponsoring the same mint again. Claims survive every uncertain call. Store original signed intent, attestation, raw transaction and receipt; a caller restart must recover those exact records.
- `settleWithDiscoveryFallback` retains its name for source imports but no longer retries on any throw. Attach Bazaar metadata to challenges/read-only verification when compatibility is uncertain. A settlement timeout cannot prove metadata rejection before debit.
- Indexer events now include transaction hash/log index and sort by block then log index. Callbacks must deduplicate and apply transactionally; partial failure replays earlier events because no new cursor is returned. No exactly-once delivery or automatic reorg handling is claimed.
- Build and pack before consumption; exports resolve to generated ESM and declarations, with explicit pinned Circle SDK/x402 runtime dependencies and compatible viem peer. `npm run test:package` validates a clean tarball consumer.

Review [provenance](provenance.md) for acceptance still owned by the application: durable-store crash/restart tests, real funded settlement, browser custody/nonce policy, fee quotes, deployment authority and chain finality. The unchanged registry contract is not newly audited by these helper tests.
